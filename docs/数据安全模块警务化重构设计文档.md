# 轻舟云警务大数据平台 · 数据安全模块警务化重构设计文档

> 版本：v1.0（设计稿）
> 范围：审计日志、变更审计、分类分级、敏感数据、我的数据、权限审批 6 个子模块
> 定位：将通用"数据安全"重构为**警务数据安全治理中心**——既是安全防线，更是**服务总线**：为 Agent 助手、警务数据接口、研判报表、数据资产、组织权限等所有模块提供定级、脱敏、审计、审批能力。

---

## 一、总体定位与设计原则

### 1.1 定位
「数据安全」不是孤立的一组后台页面，而是平台各业务模块共同的**安全基座**：

```
业务模块(Agent/接口/报表/组织/采集…) ──调 用──▶ 数据安全中心
                                              │
    ┌──────────────┬──────────────┬───────────┴──────────┐
    ▼              ▼              ▼                    ▼
 分类分级       敏感数据        审计日志              权限审批
 (定级服务)    (脱敏服务)      (留痕服务)            (审批服务)
    │              │              │                    │
    └── 接口脱敏 ──┘              └── 布控告警联动 ────┘
        报表密级                    设置审计/调用审计
        导出审批
```

### 1.2 警务化术语映射
| 通用术语 | 警务化术语 | 服务对象 |
|---|---|---|
| 分类分级 | **公安数据分类分级** | 数据资产、数据中心、实体库、接口服务 |
| 敏感数据 | **敏感字段与脱敏治理** | Agent 助手、接口服务、研判报表、个人中心 |
| 审计日志 | **警务操作审计** | 平台所有模块（查询/导出/审批/设置/调用） |
| 变更审计 | **数据与权限变更追溯** | 数据治理、实体库、权限体系 |
| 我的数据 | **我的数据权限与使用** | 民警个人（组织架构/角色数据范围联动） |
| 权限审批 | **统一审批中心** | 临时权限/跨单位协查/导出/扩容/模型调整 |

### 1.3 设计原则
1. **安全即服务（SaaS 化）**：定级、脱敏、审计、审批以服务方式被其他模块调用，非孤立页面。
2. **分级驱动**：数据密级（公开/内部/秘密/机密）驱动一切策略——脱敏强度、导出审批、共享范围、接口返回。
3. **全链留痕**：查询、导出、审批、设置、接口调用全部进入审计，审计员视角脱敏展示。
4. **统一审批**：所有"申请-审批"场景收敛到权限审批中心（临时权限/导出/扩容/模型调整/跨单位协查）。
5. **权责分离**：审计员只读审计域、管理员不可修改审计数据；权限审批权与业务角色分离。

## 二、模块详细设计

### 2.1 分类分级（公安数据分类分级）

#### 2.1.1 业务场景
《数据安全法》与公安数据管理规定要求：所有数据按**类别**（人口、轨迹、资金、通信、案件、情报…）与**级别**（公开/内部/秘密/机密）标注。分级结果驱动平台全部安全策略。

#### 2.1.2 功能设计
| 功能 | 说明 |
|---|---|
| 分类体系 | 警务数据类别：人口信息 / 轨迹数据 / 资金流水 / 通信记录 / 案件数据 / 情报数据 / 布控数据 / 场所数据 |
| 分级体系 | 四级：公开 / 内部 / 秘密 / 机密（含默认规则） |
| 表列定级 | 按表/列配置级别与类别；支持**批量定级**、按数据源同步 |
| **分级策略** | 级别默认继承（列继承表、表继承数据源、数据源继承单位）；覆盖需审批 |
| **驱动联动** | ① 接口服务：返回数据按调用方等级 vs 数据级别动态脱敏 ② 报表：密级≥秘密导出需审批 ③ Agent：高密级数据结论标注"待核实/涉密" |
| 分级变更 | 提升密级需安全审计员确认；变更入审计 |

#### 2.1.3 联动
- 消费方：数据资产（目录标注）、接口服务（脱敏）、研判报表（密级）、Agent 助手（涉密提示）。

---

### 2.2 敏感数据（敏感字段与脱敏治理）

#### 2.2.1 业务场景
全平台敏感字段台账（身份证、手机号、住址、轨迹、资金、人脸、警号）+ 脱敏规则统一治理，供所有出口动态脱敏。

#### 2.2.2 功能设计
| 功能 | 说明 |
|---|---|
| 敏感字段台账 | 表名/列名/敏感类型（身份证/手机号/住址/银行账号/轨迹/人脸/警号/案情）、级别、来源数据源 |
| 脱敏规则 | 全脱敏（前3后4）/ 部分脱敏（前6后4）/ 自定义正则；**默认规则库**（身份证/手机号/住址自动匹配） |
| 自动发现 | 基于列名/样本扫描新字段，建议入库（人工确认） |
| **脱敏引擎服务** | 提供统一脱敏 API：`mask(列, 值, 调用方等级)`；Agent 结果、接口返回、报表导出、个人中心展示全部走此引擎 |
| 规则审计 | 规则变更记录操作人与时间 |
| **豁免管理** | 特定角色/场景豁免（如研判专家），豁免操作强制审计 |

#### 2.2.3 联动
- 消费方：Agent 助手（结果打码）、警务数据接口（maskColumns 脱敏）、研判报表导出、个人中心（脱敏级别）、采集表单（涉敏感审批）。

---

### 2.3 审计日志（警务操作审计）

#### 2.3.1 业务场景
任何数据访问必须可追溯：谁（警号）、何时、哪个模块、查了/导出了什么、数据范围、是否脱敏。同时支撑异常行为识别（越权、高频、下班时段）。

#### 2.3.2 功能设计
| 功能 | 说明 |
|---|---|
| 审计记录 | 操作人（警号+姓名+单位）、模块（Agent/接口/报表/设置/审批/导出…）、动作、对象、数据范围、结果、IP、时间 |
| **敏感操作标记** | 导出、删除、不脱敏、权限变更、授权变更 → 标记"敏感"并高亮 |
| **审计聚合视图** | 今日操作量、敏感操作数、按模块/按人统计、异常操作（越权尝试/下班高频） |
| **审计员视角脱敏** | 审计员看到的姓名/警号默认脱敏，可申请明文查看（记录） |
| 审计导出 | CSV 导出（审计员），含审批记录 |
| 保留策略 | 默认 365 天，不可删除；到期归档 |
| **异常联动** | 越权访问、连续失败、高频查询 → 标记异常并推送布控告警（联动消息中心） |

#### 2.2.3 联动
- 汇聚：Agent 调用审计、接口调用审计、设置修改审计、报表导出审批、权限审批、登录审计。
- 输出：布控告警、消息中心、合规报告。

---

### 2.4 变更审计（数据与权限变更追溯）

#### 2.4.1 业务场景
追责与治理需要回答："这条数据/这个权限什么时候被谁改成了什么"。覆盖：实体属性变更、数据源结构变更、分级/脱敏规则变更、角色与数据范围变更。

#### 2.4.2 功能设计
| 功能 | 说明 |
|---|---|
| 变更记录 | 时间、对象类型（实体/数据源/规则/角色/授权）、对象、操作（新增/修改/删除/升级）、**变更前后值**、操作人 |
| 多维筛选 | 按对象/操作人/时间/对象类型 |
| **Diff 对比** | 变更前后 JSON diff 展示（改了什么字段） |
| 回滚提示 | 支持对可回滚变更发起"回滚申请"（走权限审批） |
| 保留与导出 | 与审计日志一致的保留策略与导出 |

#### 2.4.3 联动
- 汇聚：实体归一化、数据源采集、分类分级、敏感规则、角色数据范围、授权变更。

---

### 2.5 我的数据（我的数据权限与使用）

#### 2.5.1 业务场景
民警需要知道：我当前能看哪些数据（权限来源与范围）、到期时间、近期访问与导出记录——避免越权、也便于发现权限滞留（离职/调岗）。

#### 2.5.2 功能设计
| 功能 | 说明 |
|---|---|
| 我的权限 | 数据范围（本单位/部门/专案/全局）、来源（角色/组织/临时申请/专案抽调）、到期时间、状态 |
| **权限来源溯源** | 每项权限可查看授予链路（角色→组织→成员） |
| 我的访问 | 近期查询/调用/导出记录（时间、模块、对象、脱敏状态） |
| **到期预警** | 临时权限/专案抽调到期前 7 天提醒；到期自动回收 |
| 主动释放 | 主动放弃非必要权限（留痕） |
| 与个人中心联动 | 个人中心的"数据权限矩阵/操作留痕"由此模块提供数据 |

#### 2.5.3 联动
- 汇聚：组织架构（成员挂靠）、角色数据范围、权限审批（临时权限）、专案组建制。
- 输出：个人中心、消息提醒。

---

### 2.6 权限审批（统一审批中心）

#### 2.6.1 业务场景
平台所有"申请-审批"收敛为**统一审批流**：临时数据权限、跨单位协查、报表导出（秘密以上）、接口配额扩容、模型调整、回滚操作。审批链按组织层级或专案负责人。

#### 2.6.2 功能设计
| 功能 | 说明 |
|---|---|
| 审批类型 | 临时权限申请 / 跨单位协查 / 导出审批 / 配额扩容 / 模型调整 / 回滚申请 |
| 申请单 | 申请人（警号自动带出）、类型、对象、范围、期限、事由、紧急程度 |
| **审批流** | 一级/二级审批可配（部门负责人→单位管理员）；紧急可加急 |
| 状态机 | 待审批 → 通过（限时生效）/ 驳回（含意见）/ 撤销 |
| **到期自动回收** | 通过的临时权限到期自动回收并通知 |
| 审批时效 | 超时未审提醒审批人（消息中心） |
| 审批统计 | 我的申请/我的待办/历史记录；各类型审批时长统计 |
| **联动触发点** | Agent 助手"临时权限申请"、个人中心"权限矩阵"、接口"扩容申请"、报表"导出审批"、系统设置敏感操作——全部写入统一审批 |

#### 2.6.3 联动
- 汇聚：Agent 助手、个人中心、警务数据接口、研判报表、变更审计回滚。
- 输出：生效权限（写回组织/数据范围）、消息中心通知。

## 四、架构设计

### 4.1 安全服务四层
```
┌ 消费层: Agent / 接口 / 报表 / 采集 / 个人中心 / 系统设置 ┐
├ 服务层: 定级服务(分类分级) · 脱敏服务(敏感数据) · 留痕服务(审计) · 审批服务(权限审批) ┤
├ 数据层: 分级表 · 敏感字段表 · 审计表 · 审批表 · 权限表 ┤
└ 合规层: 保留策略 · 审计员脱敏视角 · 导出审批 · 异常联动布控 ┘
```

### 4.2 统一脱敏调用链
```
任何出口(Agent/接口/报表/页面) → SensitiveService.mask(col, value, callerLevel, dataLevel)
    → 规则匹配 → 打码 → 审计记录(是否脱敏) → 返回
```

### 4.3 统一审批调用链
```
业务模块 → ApprovalService.submit(type, object, scope, term, reason)
    → 审批流(一级/二级) → 通过 → 权限写入 + 到期回收定时器 → 通知
    → 驳回 → 意见回填申请人
```

## 六、风险与合规说明

1. 分级/脱敏/审计/审批均**服务化**，任何新模块接入即获得安全能力，杜绝"绕过安全出口"。
2. 审计数据不可删除、保留期 365 天，审计员视角脱敏，明文查看需审批留痕。
3. 权限变更、分级提升、规则变更、授权变更必留痕并支持追溯。
4. 临时权限/专案抽调到期**自动回收**，防止权限滞留（等保与数据安全法要求）。
