## 一、演进目标

1. **多存储统一接入**：数据源从"仅 MySQL/H2"扩展为"MySQL(主/从) + Iceberg 湖仓 + ClickHouse + Kafka + 对象存储"全谱系。
2. **湖仓分析贯通**：采集→湖仓→分析层→接口/报表全链路（ODS 入湖、湖仓加工、分析层聚合、出口服务）。
3. **实时化**：CDC(binlog) → Kafka → 湖仓/分析层，实时链路与批量统一口径。
4. **微服务化适配**：研发域由数据研发服务承载，调度主应用单飞、任务经事件总线分发；跨服务能力经网关/Feign。
5. **容灾感知**：读写分离（主从）、采集源自动切换、质量/血缘跨存储追踪。

## 二、数据源模块（添加多存储类型 + 治理增强）

### 2.1 新增数据源类型
| 类型 | 说明 | 接入方式 |
|---|---|---|
| **Iceberg 湖仓源** | 湖仓表读写（Parquet/快照） | 配置 warehouse 路径 + Catalog 类型（本地/HDFS/REST） |
| **ClickHouse 源** | 列式分析读写 | host/port/库 + 聚合查询能力标记 |
| **Kafka 流源** | 实时事件接入 | bootstrap-servers + topic 列表 + 消息格式(JSON/AVRO) |
| **MySQL 从库源** | **只读分析分流**（读写分离） | 标记 `readonly=true`，查询路由到从库 :3307 |
| 对象存储源 | 湖仓底层文件（S3/MinIO） | StorageService 复用 |

### 2.2 功能优化
| 功能 | 优化 |
|---|---|
| **测试连接** | 每类型定制校验：湖仓→建目录+读 metadata；Kafka→topic 探测；ClickHouse→SELECT 1 |
| 凭据加密 | 统一 CryptoUtil 加密存储；Kafka SASL 凭据单独加密 |
| **数据源健康** | 周期探测（经任务调度）+ 状态入监控（Prometheus gauge） |
| 读写分离路由 | 查询类任务默认走从库源，写任务强制主库源 |
| 分库分表标识 | MySQL 源标记分区/归档库（zy_archive）归属，查询自动路由 |

## 三、工作流模块（湖仓/分析/事件节点 + 微服务适配）

### 3.1 新增节点类型
| 节点 | 能力 |
|---|---|
| **湖仓写入节点** | Iceberg append/overwrite（Parquet），支持分区写入 |
| **分析加载节点** | 从湖仓/MySQL 聚合 → 写入 ClickHouse/zy_analysis |
| **Kafka 事件节点** | 发布/订阅事件（任务完成、数据变更通知） |
| **数据源切换节点** | 主从切换/归档迁移（容灾联动） |

### 3.2 优化
| 项 | 设计 |
|---|---|
| 调度执行 | 主应用 Quartz 单飞调度 → 任务经 **Kafka/任务队列** 分发到数据研发服务执行（微服务适配） |
| 数据范围校验 | 节点读取数据前校验密级/数据范围（联动安全服务） |
| 失败重试 | 指数退避 + 重试次数上限；失败事件 → Kafka → 消息中心告警 |
| DAG 血缘 | 工作流自动生成跨层血缘（源→节点→目标） |
| 湖仓快照 | 支持工作流级快照标记（可回溯版本） |

## 四、采集/同步模块（CDC 实时化 + 湖仓分析目标）

### 4.1 新增能力
| 能力 | 说明 |
|---|---|
| **CDC 实时采集** | 主库 binlog(ROW) → 解析 → **Kafka** → 消费写入湖仓/ClickHouse（基于已就绪的主从 binlog） |
| 湖仓批量同步 | MySQL → Iceberg（Spark/直写 Parquet，快照可回溯） |
| 分析层同步 | MySQL/湖仓 → ClickHouse（MergeTree，聚合口径统一） |
| 从库读取采集 | 批量采集读从库源（不压主库） |

### 4.2 优化
| 项 | 设计 |
|---|---|
| 断点续传 | 采集位点存 MySQL（binlog position/offset）+ 失败恢复 |
| 主从切换 | 采集源漂移（主库故障→从库提升后自动切换采集源） |
| 实时-批量对账 | 每日对账任务：实时入湖 vs 批量入湖行数/校验和比对 |
| 事件通知 | 采集完成/异常 → Kafka → 消息中心 |

## 五、质量模块（湖仓/实时质量 + 结果资产化）

### 5.1 新增规则类型
| 规则 | 说明 |
|---|---|
| **湖仓快照校验** | Iceberg 快照级：表行数/空值率/主键唯一性（Parquet 扫描） |
| 分析层规则 | ClickHouse 聚合质量（如区域轨迹总量阈值/波动率） |
| **实时质量** | Kafka 流式校验（字段完整性/格式），异常事件入湖 |
| 跨库一致性 | MySQL vs 湖仓 vs 分析层 行数/校验和比对 |

### 5.2 优化
| 项 | 设计 |
|---|---|
| 结果资产化 | 质量结果写入 `zy_quality_result` + 湖仓质量快照表（趋势可查） |
| 告警联动 | 质量失败 → Kafka 事件 → 消息中心 + 布控告警（联动安全服务） |
| 集群执行 | 湖仓/大表质量检查经 **Spark 提交器**执行（DRY_RUN→实连） |

## 六、血缘模块（跨存储全链路）

### 6.1 新增血缘类型
| 血缘 | 说明 |
|---|---|
| **跨层血缘** | MySQL(ODS) → Iceberg(湖) → ClickHouse/zy_analysis(分析) → 数据接口/报表(出口) |
| 湖仓快照血缘 | 表↔快照↔数据文件（Parquet 文件级） |
| **Kafka 流血缘** | topic → 消费任务 → 湖仓表（实时链路） |
| 任务血缘 | 工作流节点执行记录（谁在何时产出） |

### 6.2 优化
| 项 | 设计 |
|---|---|
| 自动采集 | 采集/工作流/接口发布时自动登记血缘（JSQLParser 解析 SQL 表依赖） |
| 数据范围传播 | 血缘沿链路传播数据范围/密级（下游继承上游） |
| 影响分析 | 血缘反向查询："改这张表会影响哪些接口/报表"（警务合规刚需） |

### 7.2 优化

## 八、引擎作业模块（Spark/Flink 提交器 × 湖仓分析）

### 8.1 新增作业模板
| 作业 | 说明 |
|---|---|
| **Spark → Iceberg 入湖** | 读取 MySQL/文件 → 写入湖仓（Parquet，快照版本） |
| **Spark 湖仓加工** | 湖仓表间 ETL（SQL 下推引擎执行） |
| **Spark → ClickHouse** | 湖仓聚合结果 → 分析层（MergeTree） |
| **Flink 流式入湖** | Kafka 事件流 → Iceberg（实时链路） |
| 湖仓导出作业 | 湖仓 → 对象存储/文件（StorageService 复用） |

### 8.2 提交器优化
| 项 | 设计 |
|---|---|
| Catalog 支持 | 提交参数含 Iceberg warehouse/Catalog 配置（本地已实连验证） |
| 集群实连 | Spark standalone 已实连（`zy-police-agg` FINISHED）；作业模板默认集群提交，无集群 DRY_RUN |
| 资源配额 | 按作业/租户限制 Executor 数、内存、执行时长 |
| 结果落资产 | 作业执行记录/指标 → 元数据 + Prometheus 埋点 |

## 十一、风险与合规

1. 湖仓/分析层数据继承上游密级与数据范围（跨层传播，防止降级绕过）。
2. CDC 采集 binlog 属敏感事件流：Kafka topic 加密/白名单，采集内容脱敏可选。
3. 主从切换须保证位点一致与切换审计（联动 mysql-dr.sh）。
4. 湖仓快照保留策略遵循数据保留期限（热/温/冷分层）。
