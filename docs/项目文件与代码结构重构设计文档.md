# 轻舟云项目文件与代码结构重构设计文档

> ⚠️ **历史存档**：本重构已完成并落地（zy-modules 68 包 → 7 域 + usercenter；现工程为 TemporeData Guard，模块 temporedata-guard-*）。文中 zy-modules/zy-main 等旧名均为**重构前基线描述**，实际以新结构为准。
>
> 版本：v1.0（设计稿）
> 目标：重新设计业务功能模块的项目文件组织与代码结构，对齐微服务架构与团队协作规范
> 现状基线：zy-modules 68 包平铺、6 拆分服务共享 modules、前端 60 views 平铺、Agent.vue 2503 行巨型组件

---

## 一、现状问题分析

| 维度 | 问题 |
|---|---|
| **后端包结构** | zy-modules 68 个业务包**平铺**（agent/ai/alarm/apilog…并列），无"域→子域→层"分级；包间依赖无约束（ArchUnit 已有部分规则但组织未分层） |
| **服务边界** | 6 拆分服务全部依赖整个 zy-modules（裁剪扫描实现边界），**jar 级未真正解耦**（代码物理耦合仍在） |
| **前后端命名** | 前端 60 views 与后端包名无对应关系；`Agent.vue` 单文件 2503 行（布局/能力面板/设置/图表混写） |
| **API 契约** | zy-api 契约类零散按模块放，无统一目录约定 |
| **配置** | 各服务 application.yml 重复度高（JWT/存储/事件/数据源模板重复） |
| **资源/测试** | 缺统一测试分层（单元/集成/契约）与资源目录规范 |

## 二、目标后端结构设计（域分层）

### 2.1 zy-modules 内部分层（包重组）

│   ├── auth/            # 认证

## 四、代码质量与治理

| 项 | 设计 |
|---|---|
| **依赖守则(ArchUnit)** | 域间依赖白名单：police/agent/dev 允许依赖 common+security；platform 不依赖业务域；违例构建失败 |
| 测试分层 | `src/test/java` 下 `unit/ integration/ contract/`（契约测试验服务间 DTO 兼容） |
| 配置中心化 | 各服务 yml 抽取公共模板 → `zy-common` 提供 `application-common.yml`（import） |
| 日志/埋点 | 统一 traceId/审计埋点约定（已内建，规范到域层） |
| 文档联动 | docs/ 每域一文档 + 包 README（新域必带） |

## 五、迁移方案（阶段）

| 阶段 | 内容 | 风险 |
|---|---|---|
| **P1 包重组(纯移动)** | zy-modules 68 包 → 7 域目录（保留原包名在域下，如 `modules/police/intelligence`）；全量编译+回归通过 | 低(import 路径批量改) |
| P2 契约重组 | zy-api 按域建目录，DTO 归类 | 低 |
| P3 前端重组 | views/api 按域目录迁移；**Agent.vue 拆 12 组件** | 中(功能回归重点) |
| P4 配置/测试 | application-common.yml 抽取；测试分层；ArchUnit 域守则启用 | 低 |
| P5 物理解耦 | 按 2.2 映射将域拆独立 jar（服务只依赖自己域+公共） | 高(依赖清理) |

**原则**：P1-P3 纯结构迁移（行为不变，逐步回归）；P4 质量治理；P5 才涉及运行边界变化。

---

## 六、风险与说明

1. 包重组涉及全部 import 路径变更：用 IDE/脚本批量改 + `mvn test` + 回归脚本兜底（44 项）。
2. Agent.vue 拆分时保持行为一致：组件 props/events 契约先行定义。
3. P5 物理解耦前，6 服务继续依赖全量 modules（现有裁剪扫描模式不变，零中断）。
4. 前端 60 视图迁移按域分组，路由 path 不变（避免书签/菜单失效）。
