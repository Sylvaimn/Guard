# 金盾智云警用大数据中台 · 警用内网环境生产部署方案设计文档

> 版本：v1.0
> 定位：模式三（试点/生产）在**警用内网/公安专网**环境下的落地设计
> 约束输入：涉密警务数据不出域、等保 2.0（三级）、公安网边界管控、无外网（离线交付）、终端准入（警务通/CA）、国产化演进可能
> 基线：技术方案 v2.0（业务需求驱动）+ 双工作台 P0-P2 全量功能

---

## 一、警用内网环境约束（设计前提）

| 约束 | 影响 |
|---|---|
| 专网物理隔离，无公网 | 依赖离线化：制品、镜像、npm/maven 仓库内网化 |
| 涉敏数据分级（L1-L4） | 密级控制、最小化部署、分区分域 |
| 等保 2.0 三级（可能四级） | 身份鉴别、访问控制、安全审计、数据完整性、入侵防范、集中管控 |
| 公安网边界与接入管控 | 边界安全设备、终端准入、跨网数据交换受控 |
| 警务终端（警务通/PC）认证 | CA 数字证书/短信/警务通扫码（系统已支持免密登录） |
| 国产化趋势 | 预留 CPU/OS/数据库/中间件国产化适配位 |

## 二、安全域与总体拓扑

```text
┌────────────────────────── 警用内网（公安专网） ──────────────────────────┐
│                                                                            │
│ [警务终端区]        警务通 / 内网 PC / 大屏        （CA/短信/扫码认证）     │
│        │ HTTPS(国密 SM2/SM4 可选)                                         │
│ [接入区]            边界防火墙 / 负载均衡(双机) / 终端准入                 │
│        │                                                                  │
│ [应用服务区]        nginx 静态集群 ×2 ──▶ 后端集群                        │
│        │              ├─ 主应用 A :8080    主应用 B :8080                 │
│        │              ├─ 拆分服务×6（按域，可多副本）                     │
│        │              └─ 网关 :8088(Nacos lb, 可选)                      │
│        │                                                                  │
│ [数据区]            MySQL 主从/集群 │ Kafka 集群 │ Nacos 集群              │
│        │            ClickHouse │ Redis │ Iceberg 湖仓(共享存储)           │
│        │                                                                  │
│ [管理区]            堡垒机 / 监控(Grafana) / 日志集中 / 备份服务器         │
│        仅管理网段可达（三员分离）                                         │
└────────────────────────────────────────────────────────────────────────────┘
```

**分域原则**：接入区-应用区-数据区-管理区四层隔离；管理区与业务区物理/逻辑隔离；数据库仅应用网段可达。

## 三、部署形态详细设计

### 3.1 前端（nginx 独立发版）
| 项 | 设计 |
|---|---|
| 制品 | `npm run build` 产物（static）→ 发布包 `web-v2.1.0.tar.gz`（含版本号） |
| 部署 | nginx 双机：`/usr/share/nginx/html/web/` 按版本目录（current 软链），发版仅替换 + 平滑 reload |
| 反代 | `location /api/ { proxy_pass http://app-cluster; }` + `/actuator` 限管理网段 |
| TLS | 内网 CA 证书或国密 SSL（SM2）网关/终端 |
| 缓存 | 静态资源 max-age（hash 文件名）；页面 no-cache |
| 版本回退 | 保留上一版本目录，current 软链回退即完成 |

### 3.2 后端双节点（主应用）
| 项 | 设计 |
|---|---|
| 部署单元 | 主应用 jar ×2（same jar，DB 共享） |
| 会话/缓存 | Redis 共享（血缘缓存等） |
| 定时任务 | Quartz 单飞策略：主应用双节点仅其一执行调度（分布式锁/任务标记），避免双跑 |
| 事件消费 | Kafka 消费组自动分配（双节点负载）；CDC/血缘/审计监听器同 group 负载均衡 |
| 前端归属 | 页面由 nginx 托管 → 后端只服务 API（前后端彻底分离） |
| 健康 | nginx upstream 探活 /actuator/health；故障自动摘除 |
| 发版 | 滚动：A 停→发→起→健康→切流量→B 同步骤（零停机） |

### 3.3 拆分服务（按域多副本）
- platform/security/data/police/agent/dev 六服务：试点期单副本（与主应用同机各 1）→ 峰值可扩副本
- 服务间不直接调用（共享 DB + Kafka 事件），扩容无会话粘滞问题
- Nacos 注册；网关(可选) lb:// 统一入口

### 3.4 数据与中间件集群化
| 组件 | 集群设计 |
|---|---|
| MySQL | 主从（binlog ROW）+ 半同步；从库可读/容灾；mysql-dr.sh 切换；备份服务器每日全备 + binlog 增量 |
| Kafka | KRaft 3 节点（容 1 故障），topic 副本 3 |
| Nacos | 3 节点集群（注册/配置） |
| Redis | Sentinel 3 节点（主从 + 哨兵） |
| ClickHouse | 单机 + 备份表导出；规模后 ReplicatedMergeTree |
| Iceberg 湖仓 | warehouse 置于**共享存储**（NFS/SAN）或 HDFS；目录快照定期备份 |
| 备份 | 全库每日 / binlog 增量 / 湖仓目录快照 / 前端版本包归档 / 配置与密钥保险柜 |

### 3.5 资源规划（试点：500 用户/日活 100，双机起步）
| 主机 | 配置 | 承载 |
|---|---|---|
| 应用节点 ×2 | 16C/32GB SSD | 主应用 + 3 拆分服务 + nginx |
| 数据节点 ×2 | 16C/64GB SSD | MySQL 主从 + 湖仓共享存储挂载 |
| 中间件 ×3 | 8C/16GB | Kafka/Nacos/Redis/ClickHouse |
| 管理 ×1 | 8C/16GB | Prometheus/Grafana/备份/日志 |

## 四、离线化交付设计（无外网关键点）

| 层 | 方案 |
|---|---|
| 制品库 | 内网 Nexus：代理并**预拉全量** maven(npm 依赖+插件) / pypi；首次构建在联网机全量下载后导入 |
| 镜像 | Docker 镜像（mysql/nacos/kafka/clickhouse/redis/prometheus/grafana）导出 tar → 内网 docker load；或内网 Harbor |
| Java 运行 | 内网 JDK 11 安装包（x86/arm 各备）；jar 自包含无外网依赖（湖仓/驱动全部打入） |
| 前端 | 构建产物全静态，无 CDN/外链（字体/图表本地化）——**需审计确认无公网资源引用** |
| 模型 | Agent 大模型：内网私有化（Ollama/vLLM 本地模型）或外网模型经边界**审批通道**（密级≤INTERNAL），禁止直连 |
| 验证 | 内网冒烟：健康检查 + 44 项回归脚本 + 页面资源完整性检查 |

## 五、等保 2.0（三级）安全加固

| 控制点 | 落实设计 |
|---|---|
| 身份鉴别 | 双因子：口令 + CA/警务通/短信；登录失败锁定；会话超时（系统已支持） |
| 访问控制 | 五级权限（菜单/按钮/数据范围/字段/密级）+ 专案边界；三员分离（系统/安全保密/审计管理员角色） |
| 安全审计 | 全链路审计（登录/查询/导出/Agent）+ zy_audit_log 等 4 类日志表；日志集中采集（管理区） |
| 入侵防范 | 最小端口；应用限流；管理网段白名单；堡垒机操作 |
| 数据完整性/保密性 | 国密 SM3 校验 / SM4 存储加密（密钥保险柜）；传输 TLS/国密 SSL |
| 集中管控 | Grafana 统一监控 + 告警；配置基线脚本 |

**国密适配位**：密码算法抽象（现有 CryptoUtil 预留算法位）；数据库加密列；CA 证书验签（SM2）。

## 六、数据安全内网强化

- **密级**：数据对象/接口/Agent 工具均带 level；超密级不暴露存在性（返回统一文案）
- **受控查询**：白名单表 + 参数化 + LIMIT + 脱敏 + zy_data_query_log 审计——警务人员不得任意 SQL
- **脱敏规则**：zy_sensitive_field 维护（管理员端）；接口/报表/Agent 出口统一脱敏
- **专案隔离**：成员可见、非成员 403、对象证据留存、动态流水
- **导出**：涉密导出走审批链（report:export + 审批 + 审计）
- **跨网交换**（如需）：经边界单向导入/导出审批，禁用介质直连

| 能力 | 设计 |

| 操作 | 堡垒机录屏审计；变更走审批 + 变更审计表 |

## 十、实施步骤与验收

### 实施步骤
| 步 | 内容 |
|---|---|
| 1 | 网络与安全域划分、主机就绪、离线制品与镜像导入 |
| 2 | 数据区部署（MySQL 主从/Kafka/Nacos/Redis/CH/湖仓共享存储）并验证复制 |
| 3 | 后端双节点 + 拆分服务部署（systemd + 统一 .env）→ Nacos 注册健康 |
| 4 | nginx 前端双机（静态 + /api 反代 + 版本目录）→ 全链路冒烟 |
| 5 | 监控/日志/告警/备份/堡垒机接入 |
| 6 | 安全加固（等保自查项）→ 三员账号与角色配置 → 审计验证 |
| 7 | 容灾演练 + 上线（业务数据初始化 + 回归 44 项 + 双工作台验收） |

### 验收标准
- [ ] 内网无外网依赖：全量离线导入完成，构建/运行不触公网（页面资源完整性检查通过）
- [ ] 双节点：杀一节点 30s 内业务恢复（nginx 摘除→健康）；Quartz 无双跑
- [ ] MySQL 切换演练成功；Kafka/Nacos/Redis 集群健康
- [ ] 前端发版：仅替换静态版本目录平滑生效，后端不停机
- [ ] 等保三级自查项闭环（身份/访问控制/审计/数据完整保密/集中管控）
- [ ] 警务用户链路验收：检索→研判→专案→受控查询(脱敏)→报告→AI；审计全量可查
