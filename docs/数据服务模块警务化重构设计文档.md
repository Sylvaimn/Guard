# 轻舟云警务大数据平台 · 数据服务模块警务化重构设计文档

> 版本：v1.0（设计稿）
> 范围：接口服务、接口日志、黑白名单、数据报表、表单管理 5 个子模块
> 目标：将通用"数据服务"重构为符合公安数据交换与合规要求的**警务数据服务域**（数据交换、调用审计、访问控制、研判报表、一线采集）。

---

## 一、总体定位与设计原则

### 1.1 定位
「数据服务」是平台的**对外数据交换与服务出口**：向公安内部业务系统（治安/刑侦/交管）、上下级机关、警务终端提供受控的数据查询与交换能力，同时承载**研判报表输出**与**一线数据采集**。所有出口必须满足：**鉴权、脱敏、审计、配额、审批**五要素。

### 1.2 警务化术语映射
| 通用术语 | 警务化术语 | 说明 |
|---|---|---|
| 接口服务 | **警务数据服务接口** | 面向内部系统/上级机关/警务终端的受控数据通道 |
| 接口日志 | **接口调用审计** | 谁（系统/警号）、何时、查了什么、多少条、是否脱敏 |
| 黑白名单 | **访问控制名单** | IP/系统标识/设备 的允许与拒绝，联动公安网边界 |
| 数据报表 | **警务研判报表** | 涉诈周报、治安态势、重点人员动态等战报模板 |
| 表单管理 | **警务采集表单** | 一线线索录入、重点人员采集、场所检查、接警登记 |

### 1.3 设计原则
1. **出口受控**：一切数据出口（接口/报表导出）必经鉴权 + 审计，敏感导出需审批。
2. **动态脱敏**：接口返回数据按**调用方数据等级**动态脱敏（调用方等级低于数据密级→脱敏字段）。
3. **调用留痕**：每一次接口调用、报表导出、表单提交均审计（调用方/数据范围/条数/结果）。
4. **异常联动**：高频调用、越权尝试、数据量突增 → 记录审计并联动布控告警。
5. **一线友好**：采集表单面向基层民警，模板化、审批化、与数据入仓打通。

## 二、模块详细设计

### 2.1 接口服务（原「接口服务」→ 更名「警务数据接口」）

#### 2.1.1 业务场景
公安大数据平台需要向以下对象提供数据服务：本局各警种业务系统（情报、治安）、上级公安机关数据交换、警务通移动终端查询、临时专案组数据抽取。每个接口的**数据范围、脱敏策略、调用对象、配额**各不相同。

#### 2.1.2 功能设计
| 功能 | 说明 |
|---|---|
| 接口 CRUD | 名称、接口路径、方法、来源表（支持单表/视图） |
| **服务对象** | 内部系统 / 上级机关 / 警务通终端 / 专案组；每个对象可单独分配 API Key 或证书 |
| **数据范围** | 本单位 / 本部门 / 专案内 / 全局（接口默认继承发布人数据范围） |
| **脱敏策略** | 按调用方数据等级自动脱敏：等级不足→身份证/手机号/住址打码；可选"仅脱敏列清单" |
| **返回限制** | 单次最大返回条数、超限截断提示、返回字段白名单（敏感字段默认排除） |
| **调用配额** | QPS 上限、每日调用上限（按调用方）；达 90% 预警、100% 拒绝并告警 |
| **发布审批** | 接口发布需管理员/数据管理员审批；审批后生成鉴权凭证 |
| 测试调用 | 测试台：选调用方身份模拟调用，预览脱敏后返回 |
| 生命周期 | 草稿→审批→发布→停用（停用立即拒绝调用并审计） |

#### 2.1.3 关键交互
- 接口详情抽屉：基本信息 + 脱敏列预览 + 调用方列表 + 配额与用量。
- 「模拟调用」：以指定调用方身份试调，展示脱敏效果与耗时。
- 停用二次确认：提示"将拒绝该接口全部调用方访问并留痕"。

---

### 2.2 接口日志（原「接口日志」→ 更名「接口调用审计」）

#### 2.2.1 业务场景
合规要求：**任何一次数据查询都必须可追溯**——民警或系统在何时、通过哪个接口、查了哪些数据、多少条、是否脱敏。同时需识别异常行为（下班后高频查询、单个接口数据量突增、越权调用）。

#### 2.2.2 功能设计
| 功能 | 说明 |
|---|---|
| 调用列表 | 接口名称、调用方（系统标识/警号）、**数据范围**、**脱敏状态**、返回条数、耗时、结果码、时间 |
| 多维筛选 | 按接口/调用方/时间段/结果码/是否脱敏/条数范围 |
| **敏感接口标注** | 涉及轨迹、资金、重点人员的接口标注"敏感"，默认高亮 |
| **异常识别** | 规则：单接口 QPS 超限、下班时段高频、返回条数突增 3 倍、连续鉴权失败 → 标记"异常"并推送布控告警 |
| 详情弹窗 | 请求参数（脱敏）、返回摘要、响应耗时、完整链路 ID |
| 审计导出 | 审计员可导出调用审计 CSV（含审批记录） |
| 保留策略 | 调用审计按系统设置保留期限存储，不可删除（仅可导出） |

#### 2.2.3 交互
- 顶部异常统计卡：今日调用量 / 异常调用数 / 敏感接口调用 / 脱敏执行率。
- 异常行红色标注 + 「查看告警」入口。

---

### 2.3 黑白名单（原「黑白名单」→ 更名「访问控制名单」）

#### 2.3.1 业务场景
数据接口的访问边界管理：只允许**公安网白名单**内的系统/终端访问数据接口；对异常 IP、被入侵终端、离职人员设备列入黑名单拒绝访问并告警。需支持网段、设备标识、系统凭证多种粒度。

#### 2.3.2 功能设计
| 功能 | 说明 |
|---|---|
| 名单类型 | 白名单（仅允许）/ 黑名单（拒绝并告警） |
| **控制对象** | IP/IP 网段 / 警务系统标识（clientId）/ 警务通设备号 / 警号 |
| 来源分类 | 公安内网网段、政务外网边界、警务通 VPN 段、外部交换专线 |
| 生效策略 | 白名单优先（显式拒绝需黑名单且非白）；黑名单命中即拒绝 + 审计 + 推送告警 |
| **联动鉴权** | 接口调用校验顺序：凭证有效性 → 名单 → 配额 → 脱敏 |
| 变更审计 | 名单增删改记录操作人/时间/原因 |
| 有效期 | 黑名单支持到期自动解除（临时封禁场景） |

#### 2.3.3 交互
- 顶部双卡：白名单命中率 / 黑名单拦截次数（今日）。
- 新增时选择对象类型并校验格式（IP/网段/CIDR）。

---

### 2.4 数据报表（原「数据报表」→ 更名「警务研判报表」）

#### 2.4.1 业务场景
民警定期输出研判材料：涉诈周报（案发趋势/高发区域/资金流向）、治安态势月报（接警/立案/破案率）、重点人员动态简报（布控触发/活动规律）。报表需**口径统一、数据范围受控、导出审批**。

#### 2.4.2 功能设计
| 功能 | 说明 |
|---|---|
| 报表模板 | 内置模板：**涉诈研判周报、治安态势月报、重点人员动态简报、专案阶段报告**；自定义模板（SQL/指标组合） |
| 报表属性 | 名称、类型（周报/月报/专报）、数据范围（本单位/全局）、**密级**（内部/秘密/机密） |
| **口径说明** | 每指标标注计算口径（如"立案数=当日立案登记数"），保证上下口径一致 |
| **生成与调度** | 按周期自动生成（周一 8:00 涉诈周报）；生成任务可查看状态 |
| **导出审批** | 密级≥秘密的报表导出需审批（申请事由/期限）；审批通过自动脱敏导出 |
| 报表内容 | 统计卡片 + 趋势图 + 附件（关联数据截图/研判要点）；AI 助手可辅助生成 |
| 分享 | 站内共享给同组/领导（联动消息中心） |

#### 2.4.3 交互
- 报表卡片视图：模板封面 + 最近生成时间 + 密级标签。
- 「生成」按钮 → 任务队列（异步），完成后消息通知。
- 导出弹窗：选择范围/审批申请（秘密以上必填事由）。

---

### 2.5 表单管理（原「表单管理」→ 更名「警务采集表单」）

#### 2.5.1 业务场景
一线民警需要标准化的**采集录入**工具：案件线索登记、重点人员基础信息采集、场所检查记录、值班接警登记。表单由管理员模板化配置，民警填写提交后数据入仓参与研判；填写过程留痕、审批可配。

#### 2.5.2 功能设计
| 功能 | 说明 |
|---|---|
| 表单模板 | 名称、描述、分类（**线索登记/人员采集/场所检查/接警登记**） |
| **模板字段** | 字段类型（文本/数字/日期/下拉/定位）、必填、**敏感字段标注**（脱敏展示）、默认值 |
| **填报人信息** | 自动带出警号/姓名/单位，不可修改（身份防伪） |
| 表单状态 | 草稿 → 已提交 → 已审批 → 已驳回（含意见） |
| **审批流** | 可配置审批人（部门负责人/专案负责人）；涉敏感字段（人员身份证）默认需审批 |
| **数据入仓** | 提交即写入采集主题表（与采集任务/实体归一化联动），供研判使用 |
| 填报审计 | 填报/修改/撤回全程留痕 |
| 模板复用 | 支持复制模板、批量导入字段 |

#### 2.5.3 交互
- 模板卡片：分类标签 + 填报量 + 最近提交。
- 填报表单：按模板动态渲染，底部显示填报人（警号自动带出）。
- 驳回：审批意见回填，民警修改后重新提交。

## 三、架构设计

### 3.1 数据出口控制链（五要素）
```
调用/导出请求
  → ① 凭证鉴权（API Key/证书/登录态）
  → ② 访问名单（白/黑名单，公安网边界）
  → ③ 数据范围校验（调用方等级 × 接口范围）
  → ④ 动态脱敏（按调用方数据等级）
  → ⑤ 配额控制（QPS/每日/条数）
  → 响应 + 全程审计留痕（异常联动布控）
```

### 3.2 接口-调用方-审计关系
```
接口(数据范围+脱敏+配额)
   ├─ 服务对象(内部系统/上级机关/警务通/专案组) → 凭证
   └─ 调用记录(调用方/范围/脱敏/条数/耗时) → 审计 + 异常识别
```

### 3.3 报表/表单合规链
```
报表：模板(口径+密级) → 周期生成(任务) → 导出审批(密级≥秘密) → 脱敏导出 + 审计
表单：模板(字段+敏感标注) → 民警填报(警号自动带出) → 审批(敏感需批) → 入仓研判 + 留痕
```

### 3.4 后端模块划分建议
| 现有 | 重构后 |
|---|---|
| DataApiController | PoliceApiController（接口+服务对象+脱敏+配额） |
| ApiLogController | ApiAuditController（审计+异常识别+导出） |
| BlacklistController | AccessControlController（名单+边界+联动） |
| ReportController | PoliceReportController（模板+调度+审批导出） |
| FormController | CollectFormController（模板+填报+审批+入仓） |

## 五、风险与合规说明

1. 接口返回、报表导出均受**动态脱敏**约束；敏感字段（身份证/手机号/轨迹/资金）默认打码。
2. 每一次调用与导出**全程审计**，审计数据不可删除，保留期遵循系统设置。
3. 涉密报表导出、涉敏感字段采集一律走**审批流**。
4. 异常调用（高频/越权/突增）**自动识别并联动布控告警**，防止数据泄露与滥用。
5. 数据范围遵循组织架构与角色数据范围（联动系统管理模块）。
