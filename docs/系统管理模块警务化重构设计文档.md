# 轻舟云警务大数据平台 · 系统管理模块警务化重构设计文档

> 版本：v1.0（设计稿）
> 范围：租户成员、角色管理、组织架构、免密登录、通知配置、后台设置→系统设置、平台授权 7 个子模块
> 目标：将通用 SaaS 管理功能重构为贴合公安信息化实际业务（等保 2.0、数据安全法、公安网络边界、警务编制与专案协同）的平台治理体系。

---

## 一、总体定位与设计原则

### 1.1 定位
「系统管理」是平台治理中心，面向**平台管理员 / 单位管理员 / 安全审计员**三类管理者，覆盖：**组织与人员、权限与角色、认证与访问、通知与预警送达、平台基础与合规配置、采购授权**六大治理域。

### 1.2 警务化术语映射
| 通用术语 | 警务化术语 | 说明 |
|---|---|---|
| 租户 | **单位（公安机关建制）** | 市局/分局/县局/派出所/专案组等有独立数据边界的建制单位 |
| 租户成员 | **单位成员** | 民警/辅警，以**警号**为唯一身份标识 |
| 组织架构 | **公安组织树** | 机关→警种部门→派出所→专案组，含临时专案建制 |
| 角色 | **警务角色** | 情报研判员、一线侦查员、值班员等，绑定数据范围 |
| 免密登录 | **公安网免密认证** | 内网 SSO / CA 证书 / 警务通扫码，配合短信二次验证 |
| 通知配置 | **预警与消息送达配置** | 按预警级别映射站内信/短信/警务通APP/应急广播 |
| 后台设置 | **系统设置** | 登录安全、数据治理、审计合规、集群引擎 |
| 平台授权 | **采购合规授权** | 授权单位、模块、数据量、用户数、期限，超期降级 |

### 1.3 设计原则
1. **权责分离**：管理员、审计员、业务角色互斥，审计员只读、不可被管理员编辑其审计日志。
2. **最小权限与数据范围**：权限 = 功能权限（RBAC） × 数据范围（本单位/本部门/专案/全局）× 数据等级（密级）。
3. **全程留痕**：管理操作（人员增删改、角色变更、授权变更、设置变更）全部审计，不可篡改。
4. **合规前置**：等保 2.0 三级要求（身份鉴别、访问控制、安全审计、数据完整性）内建到各模块。
5. **专案协同**：支持临时建制（专案组）的建立、成员挂靠与自动解散。

## 二、模块详细设计

### 2.1 单位与成员（原「租户成员」→ 更名「单位管理」）

#### 2.1.1 业务场景
公安大数据平台按**建制单位**隔离数据：市局情报中心、区分局刑警大队、派出所、专案组各自拥有独立数据边界与审批链。民警调岗、借调、离职时需同步变更数据权限，防止权限滞留。

#### 2.1.2 功能设计
| 功能 | 说明 |
|---|---|
| 单位列表 | 树形/表格展示单位（编码、名称、级别、警种、负责人、成员数、状态） |
| 单位类型 | 省厅 / 市局 / 分局 / 县局 / 派出所 / 业务警种部门 / 专案组（临时） |
| 单位属性 | 单位编码（警务机构编码）、上级单位、警种（刑侦/治安/网安/经侦/禁毒/技侦/情报…）、负责人、联系电话、创建时间 |
| 成员管理 | 成员列表 + 邀请/添加/调岗/借调/离职操作 |
| 成员字段 | **警号（唯一）**、姓名（脱敏）、单位、部门、警种、职务、**密级**、在职状态、手机号（脱敏）、警务通号、最近登录 |
| 成员生命周期 | 入职→在职→借调（挂原单位+借调单位）→调岗（权限迁移）→离职（**权限冻结+审计保留**） |
| 状态流转 | 启用 / 停用 / 冻结（离职、离岗待审） |
| 数据隔离 | 成员仅可见本单位数据边界（与组织架构联动） |

#### 2.1.3 关键交互
- 停用/离职二次确认：提示"将移除其全部数据访问权限并冻结账号，操作留痕"。
- 借调：选择借调单位与期限，到期自动收回原单位权限。
- 成员详情抽屉：基本信息 + 当前角色 + 数据范围 + 最近操作。

---

### 2.2 角色管理（警务角色）

#### 2.2.1 业务场景
警务平台角色需与**警种职能**对应，且不同角色的**数据范围**天然不同（一线侦查员看本单位案件，研判员可看专案聚合，审计员只能看审计数据）。

#### 2.2.2 内置角色（受保护，不可删除）
| 角色 | 编码 | 职能 | 数据范围（默认） |
|---|---|---|---|
| 系统管理员 | ADMIN | 平台治理与配置 | 全局 |
| 安全审计员 | AUDITOR | 审计日志、合规检查（**只读**，与管理权互斥） | 全局（仅审计域） |
| 单位管理员 | UNIT_ADMIN | 本单位人员与权限管理 | 本单位 |
| 情报研判员 | ANALYST | 情报检索、关联分析、报告生成 | 本单位 + 被授权专案 |
| 一线侦查员 | INVESTIGATOR | 案件数据查询、轨迹与资金分析 | 本单位 + 参与案件 |
| 案件管理员 | CASE_MANAGER | 案件建档、串并、成员管理 | 本案件 |
| 数据管理员 | DATA_MANAGER | 数据源接入、质量规则、标准治理 | 全局（仅数据域） |
| 值班接警员 | DISPATCHER | 预警接收、线索录入与派发 | 本单位 |

#### 2.2.3 功能设计
| 功能 | 说明 |
|---|---|
| 角色 CRUD | 名称/编码/说明；内置角色不可删、不可改编码 |
| **数据范围配置** | 本单位 / 本部门 / 专案内 / 全局；可配置默认范围 |
| **功能权限树** | 按模块勾选（情报、轨迹、资金、报告、管理、审计…） |
| 角色成员 | 成员列表、按角色查看成员 |
| 权限互斥校验 | 同一成员不可同时具有 ADMIN 与 AUDITOR；分配时提示 |
| 变更审计 | 角色权限变更记录（谁、何时、改了什么） |

### 2.3 组织架构（公安组织树）

#### 2.3.1 业务场景
公安组织呈典型**树状建制**：市局→分局→派出所；同时存在**临时建制**（专案组）跨单位抽调成员。组织架构需支撑：人员归属、数据范围推导、审批链路（按组织层级）与专案协同。

#### 2.3.2 功能设计
| 功能 | 说明 |
|---|---|
| 部门树 | 树形展示：机关→警种部门→派出所→专案组；支持拖拽/调整层级 |
| 部门属性 | 部门编号、名称、警种、负责人、编制人数、创建时间、状态 |
| 部门 CRUD | 新增/编辑/删除（仅空部门可删）；专案组标记"临时" |
| **专案组建制** | 创建专案组（关联案件、抽调成员、指定期限）；到期自动转归档并收回抽调成员权限 |
| 成员挂靠 | 一人可挂多部门（专案组成员同时挂原部门）；主单位+借调单位展示 |
| 数据范围推导 | 成员默认数据范围 = 其所属部门范围（联动角色数据范围） |
| 跨单位协同 | 专案组默认可访问专案相关数据，审批链按专案负责人 |

#### 2.3.3 交互
- 左右布局：左部门树，右侧部门成员/属性。
- 专案组卡片带「临时」标签与到期倒计时。
- 删除部门前校验：存在成员或下级部门时禁止。

### 2.4 免密登录（公安网免密认证）

#### 2.4.1 业务场景
民警在**公安内网**高频登录，密码输入繁琐；同时需满足等保"双因素鉴别"。平台在公安网边界提供免密认证能力：内网域信任后免密进入，重要操作（导出、审批、配置）触发二次验证。

#### 2.4.2 功能设计
| 功能 | 说明 |
|---|---|
| 认证方式 | 公安内网 SSO（域/单点） / **CA 数字证书** / **警务通扫码** / 短信验证码 |
| 配置项 | 登录方式、状态、适用范围（全部单位/指定单位）、优先级 |
| 安全策略 | **设备绑定**（仅绑定警务终端/指定 IP 段）、时段限制（如夜间禁止免密）、连续失败锁定 |
| 二次验证 | 免密进入后，高风险操作（导出/审批/配置）强制短信/CA 二次确认 |
| 审计 | 每次免密登录留痕（时间/设备/IP/认证方式/结果） |

#### 2.4.3 交互
- 配置列表（方式/状态/范围/优先级/启用）。
- 新增配置表单：认证方式、适用范围、设备与时段策略。
- 「测试连接」：模拟认证流程，返回成功/失败原因。

### 2.5 通知配置（预警与消息送达）

#### 2.5.1 业务场景
警务预警必须**分级、及时、可达**：紧急预警（布控对象出现、重点人员异常）需短信+APP+应急广播同步触达；一般消息仅站内信。需统一管理渠道、模板与静默策略。

#### 2.5.2 功能设计
| 功能 | 说明 |
|---|---|
| 渠道管理 | 站内信 / 短信（运营商网关）/ **警务通 APP 推送** / 邮件 / **应急广播**；每渠道可启用/停用、配置接入参数（网关地址、签名、密钥） |
| **级别-渠道映射** | 紧急→短信+APP+应急广播；重要→APP+站内信；一般→站内信（可自定义） |
| 场景模板 | 模板库：布控预警、线索流转、审批通知、任务完成、系统公告；变量占位符（{姓名}、{案件}、{时间}） |
| 送达策略 | 静默时段（夜间仅紧急）、**去重窗口**（同人同类型 30 分钟合并）、失败重试（3 次，指数退避）、**送达回执** |
| 配额与限流 | 每用户每日短信上限、渠道限流、紧急通道预留 |
| 测试发送 | 单条测试短信/推送验证通道可用性 |

#### 2.5.3 交互
- 顶部「渠道健康」卡片（各渠道状态/今日发送量/失败率）。
- 列表：名称、渠道类型、启用状态、今日送达数。
- 配置弹窗：接入参数 + 级别映射勾选。

### 2.6 系统设置（原「后台设置」更名）

#### 2.6.1 定位
从"杂项后台配置"重构为**平台治理与合规设置中心**，按治理域分组。

#### 2.6.2 设置分组
| 分组 | 设置项 |
|---|---|
| 系统信息 | 版本、构建时间、运行环境、数据库、运行时长、集群节点 |
| **登录与账户安全** | 密码策略（长度/复杂度/有效期/历史禁止）、失败锁定阈值与时长、会话超时、**双因素开关**、登录审计开关 |
| **数据治理** | **默认脱敏级别**、数据保留期限（原始数据/明细/报告分级）、**导出审批开关**、数据分级默认值 |
| **审计合规** | 审计开关、审计日志保留时长、操作留痕级别（全部/仅敏感）、合规策略引用（等保/数据安全法条款） |
| **高可用与引擎** | 集群节点数、主备切换、调度引擎、模型服务入口（对接 Agent 模型策略）、大数据引擎参数 |
| 安全边界 | 公安网 IP 白名单、外部访问开关、跨网边界提示 |

#### 2.6.3 交互
- 分组卡片式（沿用现有卡片布局，按治理域重组）。
- 敏感设置（关闭审计、降低脱敏）需二次确认 + 审计 + 提示合规风险。

### 2.7 平台授权（采购合规授权）

#### 2.7.1 业务场景
平台按**采购合同**授权：授权单位（某公安局）、授权模块（情报/轨迹/资金…）、数据量配额（亿级条数）、用户数、有效期。需支持：安装授权文件、到期提醒、超期降级、模块级校验。

#### 2.7.2 功能设计
| 功能 | 说明 |
|---|---|
| 授权信息卡 | 授权单位、项目名称、授权模块清单、数据量配额、用户数、有效期、状态 |
| 状态管理 | 有效 / **即将到期**（30 天预警，橙色）/ 已过期（红色）/ 未授权 |
| **超期降级** | 过期后：禁止新增数据写入、禁止新建用户，仅保留查询与审计导出（合规保留） |
| **模块级校验** | 授权模块未含时，对应菜单灰显并提示"未授权模块" |
| **数据量校验** | 达到配额 90% 预警、100% 阻止写入（管理员可申请扩容） |
| 并发/用户校验 | 超出授权用户数时拒绝新登录（审计提示） |
| 安装与更新 | 上传授权文件（.lic）、校验签名与指纹、更新授权 |
| 授权审计 | 授权安装/变更记录留痕 |

#### 2.7.3 交互
- 顶部授权状态卡（有效/到期预警/过期降级）。
- 「安装许可证」弹窗：上传文件、校验、回显授权信息，二次确认。
- 授权明细表：模块/配额/用户/期限。

## 三、架构设计

### 3.1 权限模型（三维）
```
访问权限 = 功能权限(RBAC 角色) × 数据范围(单位/部门/专案/全局) × 数据等级(密级/脱敏)
```

### 3.2 组织-成员-角色三角
```
组织架构(树) ──挂靠── 成员(警号唯一) ──分配── 角色(含数据范围)
     │                                        │
     └──── 数据边界推导 ──→ 单位数据隔离      └──→ 功能权限控制
```

### 3.3 通知送达抽象（Channel SPI）
```
预警/审批/任务事件 → 通知编排器 → [级别×渠道映射] → Channel 适配器
                    （去重/静默/重试/回执）         (SMS/APP/邮件/站内/广播)
```

### 3.4 授权拦截链
```
请求 → LicenseFilter(有效性/模块/配额/用户数) → 数据写拦截(配额) → 审计
```

### 3.5 后端模块划分建议
| 模块 | 现有 | 重构后 |
|---|---|---|
| 租户成员 | TenantController | UnitController（单位管理）+ UnitMemberController |
| 角色 | RoleController | PoliceRoleController（含数据范围） |
| 组织 | OrgController | OrgTreeController + SpecialCaseGroupController |
| 免密登录 | PasswordlessController | AuthPolicyController（SSO/CA/警务通/二次验证） |
| 通知配置 | NotifyController | ChannelController + TemplateController + MappingController |
| 后台设置 | SettingsController | GovernanceSettingsController（按治理域分组） |
| 平台授权 | LicenseController | LicenseController（增加模块/配额/降级校验） |

## 五、风险与合规说明

1. 所有涉及人员信息（姓名/警号/手机号）按**脱敏级别**展示，后台管理也遵循（审计员视角默认脱敏）。
2. 权限变更、授权变更、敏感设置变更**必留审计**，审计数据不可由管理员直接修改。
3. 数据保留期限、导出审批等遵循《数据安全法》《个人信息保护法》及公安部相关规定。
4. 超期降级不影响审计导出与历史数据合规保留，防止执法数据丢失。
