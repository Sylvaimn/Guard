# 金盾智云大数据平台 · 前端界面功能设计文档（管理员端与用户端详细重构版）

> 版本：v2.0  
> 基线：现有《前端界面功能设计文档（详细版）》v1.1  
> 技术栈：Vue 3 + Vite + Pinia + Vue Router + Element Plus + @vue-flow/core + ECharts  
> 产品定位：警务大数据中台 + 警务实战工作台 + AI 智能研判入口  
> 核心变化：在保留既有业务能力、页面路径和公共组件体系的基础上，按照账户角色、菜单权限、操作权限、数据范围、密级、单位/部门、专案进行管理员端与用户端分化。

---

## 1. 设计目标

### 1.1 重构目标

现有设计以完整平台能力为主，包含资源管理、数据研发、数据运维、数据监控、警务实战、数据安全、数据资产、数据服务、系统管理、个人中心以及独立 Agent。v2.0 不删除这些基础能力，而是将其重新组织为：

```text
金盾智云大数据平台
├── 公共访问层
│   ├── 登录/认证
│   ├── 权限加载
│   ├── 消息中心
│   ├── 个人中心
│   └── AI Agent
├── 管理员端
│   ├── 平台管理
│   ├── 数据研发
│   ├── 数据运维
│   ├── 数据监控
│   ├── 数据安全
│   ├── 数据资产治理
│   ├── 数据服务管理
│   └── 系统管理
└── 用户端
    ├── 用户工作台
    ├── 警务实战
    ├── 数据中心
    ├── 数据资产
    ├── 数据服务
    ├── 我的数据
    ├── 我的任务
    └── AI 智能研判
```

### 1.2 设计原则

1. **同平台、双工作台**：管理员与用户使用同一前端工程和设计体系，但登录后进入不同工作台。
2. **能力复用、权限隔离**：组件、API、状态管理和业务能力尽量复用，页面入口和操作范围由权限决定。
3. **菜单权限不等于数据权限**：用户即使拥有某菜单，也只能访问授权数据。
4. **页面权限、按钮权限、字段权限、数据权限分层控制**。
5. **密级内生**：检索、详情、图谱、导出、Agent 工具均执行密级校验。
6. **专案优先**：涉及案件/专案的数据以当前专案范围作为重要数据边界。
7. **用户端以业务为中心**：减少平台技术菜单，突出查询、研判、数据使用和申请。
8. **管理员端以治理为中心**：突出平台资源、数据研发、安全、运维和系统配置。
9. **AI 不绕过权限**：Agent 的所有工具调用继承当前账户的完整权限上下文。
10. **少菜单、少跳转**：通过工作台卡片、快捷入口、抽屉和页内详情完成高频操作。

# 2. 账户与角色体系

## 2.1 账户模型

账户由以下核心属性构成：

| 属性 | 说明 |
|---|---|
| accountId | 账户唯一标识 |
| username | 登录账号 |
| displayName | 用户显示名称 |
| tenantId | 所属单位 |
| orgId | 所属部门 |
| roles | 角色集合 |
| dataScopes | 数据范围 |
| securityLevel | 用户最高可访问密级 |
| projectScopes | 可访问专案 |
| status | 启用/禁用 |
| permissions | 菜单、按钮、操作权限集合 |

## 2.2 建议角色

| 角色 | 定位 | 工作台 |
|---|---|---|
| SUPER_ADMIN | 平台超级管理员 | 管理员 |
| PLATFORM_ADMIN | 平台管理员 | 管理员 |
| DATA_ADMIN | 数据治理管理员 | 管理员 |
| DATA_DEVELOPER | 数据研发人员 | 管理员/研发工作台 |
| SECURITY_ADMIN | 数据安全管理员 | 管理员 |
| AUDITOR | 审计人员 | 管理员/审计工作台 |
| POLICE_USER | 普通警务用户 | 用户 |
| CASE_USER | 专案业务用户 | 用户 |
| VIEWER | 只读用户 | 用户 |

> 实际角色不强制绑定单一界面。用户可以同时拥有多个角色，前端根据权限集合合并菜单；角色冲突时采用“最小授权原则”和数据范围限制。

# 3. 权限体系

## 3.1 五级权限

```text
账户
 ↓
角色权限
 ↓
菜单/路由权限
 ↓
页面操作权限
 ↓
数据/字段/密级权限
```

### 3.1.1 菜单权限

控制：

- 一级菜单
- 二级菜单
- 路由
- Tab
- 页面入口

### 3.1.2 操作权限

统一权限编码：

```text
resource:view
resource:create
resource:update
resource:delete
resource:download
resource:lineage

workflow:view
workflow:create
workflow:update
workflow:execute
workflow:delete
workflow:publish

dataasset:view
dataasset:apply
dataasset:export
dataasset:authorize

intelligence:view
intelligence:detail
intelligence:graph
intelligence:export

watch:view
watch:create
watch:dispose
```

### 3.1.3 数据范围

支持：

```text
ALL
TENANT
ORG
SELF
PROJECT
CUSTOM
```

示例：

```text
刑侦支队用户
→ 本单位
→ 本部门
→ 当前专案
→ 用户授权数据
```

### 3.1.4 字段权限

字段级控制：

```text
姓名
身份证号
手机号
住址
人脸图像
车辆信息
通信信息
```

展示方式：

```text
完整显示
部分脱敏
完全隐藏
```

### 3.1.5 密级权限

沿用现有：

```text
L1 绝密
L2 机密
L3 内部
L4 公开
```

用户只能访问不高于自身授权级别的数据。

# 33. 总结

本次重构的核心不是把管理员菜单“隐藏给用户”，而是建立：

```text
                    金盾智云大数据平台
                           │
             ┌─────────────┴─────────────┐
             │                           │
        管理员工作台                  用户工作台
             │                           │
      平台资源与数据治理             警务业务与数据使用
             │                           │
      研发 / 运维 / 安全              检索 / 研判 / 案件
      资产 / 服务 / 系统              数据 / 服务 / 申请
             │                           │
             └───────────┬───────────────┘
                         │
                   统一权限体系
                         │
       ┌─────────────────┼─────────────────┐
       │                 │                 │
     RBAC             数据范围           密级
       │                 │                 │
       └─────────────────┼─────────────────┘
                         │
                     Agent 安全
```

最终形成“**一个平台、两个工作台、一套权限体系、一套公共组件、两类业务体验**”的前端架构。
