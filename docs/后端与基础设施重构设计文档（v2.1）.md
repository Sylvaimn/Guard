## 一、重构目标与总体设计

### 1.1 目标
前端已重构为"一个平台、两个工作台"（管理员端 /admin/* + 用户端 /workbench），后端需同步：
1. **认证分流**：登录返回 roles → 前端决定工作台；后端提供 /api/auth/me 等权限接口
2. **五级权限**：菜单/操作（按钮）/数据范围/字段/密级 → 后端 RBAC + ABAC 统一校验
3. **用户端业务 API**：工作台/警务实战/专案中心/数据中心/数据服务/成果中心/我的 全量接口
4. **受控查询**：用户不能任意 SQL，后端执行 权限→数据范围→密级→字段脱敏 链
5. **Agent 权限继承**：工具调用携带完整权限上下文，输出脱敏

### 1.2 总体架构（后端视角）

```text
前端(管理员端/用户端)
        │  JWT + 权限上下文(accountId/tenantId/orgId/roles/dataScopes/securityLevel/projectScopes)
        ▼
后端权限内核
   ┌───────────────────────────────────────────────┐
   │  AuthGuard(认证) → PermissionGuard(RBAC)      │
   │  DataScopeGuard(数据范围) → DensityGuard(密级) │
   │  FieldMask(字段脱敏) → AuditInterceptor(审计)  │
   └───────────────────────────────────────────────┘
        │
   ┌────┴───────────┬──────────────┬──────────────┐
   ▼                ▼              ▼              ▼
管理员域(治理)     用户域(业务)    专案域          Agent 域
数据源/工作流/运维   情报/对象/图谱   专案CRUD/成员   工具调用(继承权限)
安全/资产/系统      线索/预警/数据   任务/线索/对象   输出脱敏+审计
```

### 1.3 后端不变量（保留）
- 数据源插件化 / 工作流引擎（含数据范围校验）/ CDC 三消费者 / 湖仓时间旅行 / 跨层血缘（含资源血缘）/ 引擎模板+配额 / 统一元数据目录 / 接口血缘 —— 全部保留为平台核心能力
- 6 拆分服务 + Nacos 注册 + 事件监听条件化（app.lineage.enabled / app.audit.listener.enabled）不变
- MySQL 主从容灾 / Kafka 事件总线 / ClickHouse 分析层 / Prometheus+Grafana 监控不变

## 二、认证与工作台分流

### 2.1 现有基础
- `POST /api/auth/login` → LoginRes{token, user{userId, username, tenantId, tenantName, **roles**, density}}
- UserEntity.roles（@ManyToMany zy_user_role → zy_role.code）→ LoginUser.roleCodes

### 2.2 新增接口
| 接口 | 说明 | 返回 |
|---|---|---|
| `GET /api/auth/me` | 当前登录用户完整信息（前端已存 localStorage，后端兜底刷新） | UserInfoRes + orgId + dataScopes + securityLevel |
| `GET /api/auth/permissions` | 当前用户操作权限集合（角色→权限编码扁平化） | `List<String>`（如 ["workflow:execute","dataasset:export"]） |
| `GET /api/auth/menus` | 当前用户可见菜单（按角色过滤，管理员/用户两套） | 菜单树（group/children/path/title/icon/permission） |
| `GET /api/auth/data-scopes` | 数据范围声明（ALL/TENANT/ORG/SELF/PROJECT/CUSTOM + 具体 orgIds/projectIds） | DataScopeRes |
| `GET /api/user/workbench` | 用户工作台聚合数据（待办/专案/预警/检索/申请状态/统计） | WorkbenchRes |

### 2.3 工作台判定（前后端一致）
- 前端：`roles` 命中 `/ADMIN|DEVELOPER|AUDITOR|SECURITY/i` → /admin/*；否则 /workbench
- 后端：`GET /api/auth/me` 返回 `workspace` 字段（admin/user）供前端兜底校验

## 三、五级权限体系（后端落地）

### 3.1 菜单权限
- `zy_role_menu`（role_id, menu_code）：角色 → 菜单/路由授权
- `GET /api/auth/menus` 按角色过滤返回

### 3.2 操作（按钮）权限
- 权限编码统一（与前端 v-permission 一致）：
  `resource:view/create/update/delete/download/lineage` · `workflow:view/create/update/execute/delete/publish`
  `dataasset:view/apply/export/authorize/query` · `intelligence:view/detail/graph/export`
  `watch:view/create/dispose` · `project:view/create/update/member/clue/report` · `report:view/create/export`
- 存储：`zy_role_permission`（role_id, permission_code）或角色表 JSON 字段
- 后端校验：`@RequirePermission("dataasset:export")` 注解 + AOP 拦截（失败 403）

### 3.3 数据范围
- `zy_role.data_scope`（现有列：ALL/TENANT/ORG/SELF/PROJECT/CUSTOM）
- 扩展 `zy_user_data_scope`（user_id, scope_type, org_id, project_id）支持 CUSTOM
- 后端注入：查询拦截器按范围自动附加条件（org_id = 当前部门 / tenant_id = 本单位 / project_id IN 授权专案 / user_id = 本人）

### 3.4 字段权限与脱敏
- `zy_column_metadata.security_level`（现有）+ `zy_sensitive_field`（表/字段/敏感类型/脱敏规则）
- 后端统一脱敏引擎（现有 SensitiveUtil 扩展）：
  - 姓名/身份证/手机/住址/人脸/车辆/通信 —— 按调用方 securityLevel 分级脱敏（全脱敏/部分脱敏/隐藏）
- 响应拦截：`@MaskField` 或统一 DataMaskInterceptor（查询结果按字段配置脱敏）

### 3.5 密级
- LoginUser.density（现有）+ securityLevel（用户最高可访问）
- 数据表/字段/接口/Agent 工具均带 securityLevel；访问校验 `数据级 ≤ 用户级`，不足返回"该数据存在，但当前账户无权查看详细信息"（不暴露存在性）

## 六、受控数据查询与脱敏

### 6.1 查询链（后端强制）
```text
POST /api/data/query {table, fields[], conditions[]}
  ↓
1. 数据对象授权校验（dataasset:query + catalog 授权记录）
2. 数据范围校验（tenat/org/project/self）
3. 字段权限过滤（未授权字段剔除）
4. 密级校验（字段 security_level ≤ 用户 securityLevel）
5. 组装安全 SQL（白名单表/字段，参数化条件，LIMIT 上限）
6. 执行 → 结果字段脱敏（DataMaskInterceptor）
7. 审计留痕（zy_query_log: 用户/对象/条件/时间）
```

### 6.2 禁止项
- 用户不可直接执行任意 SQL（前端不提供任意 SQL 入口，后端拒绝非白名单表/字段）
- 查询上限：默认 LIMIT 200，超限提示

## 九、Agent 权限继承

### 9.1 上下文透传
```text
前端(用户工作台)                   后端 Agent 域
当前用户 + 当前专案 + 数据范围 + 密级
        │  /api/agent/chat 头: X-Project-Id + JWT
        ▼
AgentService.chat → 权限上下文(LoginUser + projectScopes)
        ▼
工具调用(现有 AnalysisAgent.tryAnalyze)
  ├─ AiDensityGuard: 工具密级 ≤ 用户密级
  ├─ DataScopeGuard: 检索范围 = 用户范围 ∩ 专案范围
  ├─ FieldMask: 工具结果字段脱敏
  └─ 审计: 工具调用记录(zy_ai_trace)
```

### 9.2 新增
- `AgentSecurityGuard`（现有 AiDensityGuard 扩展）：校验工具所需 permission（entity_search→intelligence:view、track_query→intelligence:detail+CONFIDENTIAL、graph_expand→intelligence:graph）
- 用户端 Agent 默认只暴露警务工具集（检索/研判/图谱/布控/报告），管理工具（治理/SQL/运维诊断）仅管理员可见
- 输出统一"结论+证据+操作"结构，敏感字段脱敏后进 LLM 总结

## 十二、前后端接口权限约定

1. 前端只做第一层（隐藏入口/按钮/路由 meta.permission），**后端每次请求二次校验**
2. 业务请求上下文（JWT 解出）：accountId / tenantId / orgId / roles / dataScopes / securityLevel / projectScopes（X-Project-Id）
3. 敏感数据响应必须脱敏（后端强制，前端不依赖）
4. 数据不存在与无权限区分（不暴露敏感资源存在性）
5. 审计：登录/查询/导出/Agent 工具/权限申请全链路留痕

## 十四、验收标准

- [ ] police 登录 → /api/auth/me 返回 workspace=user + dataScopes + securityLevel
- [ ] 用户仅见授权菜单（/api/auth/menus 过滤）
- [ ] 受控查询：无授权数据被拒、超密级字段被拒、敏感字段脱敏、查询审计落库
- [ ] 专案：成员可见、非成员 403、对象/线索/任务/报告 CRUD 权限正确
- [ ] 数据申请：发起→审批→授权→我的数据 全流程
- [ ] Agent：用户工具集仅警务工具，工具调用继承密级/范围，输出脱敏，调用可审计
- [ ] 管理员端五级权限配置界面生效（角色→菜单/按钮/数据范围/密级）
