## 一、总体架构

```text
登录页 /login
    │ 认证(JWT) + roles
    ▼
工作台分流（前端判定，后端 roles 兜底）
    ├── ADMIN/DEVELOPER/AUDITOR/SECURITY 系 → 管理员端 /admin/dashboard
    └── 其他角色（POLICE_USER 等）        → 用户端 /workbench
```

| 端 | 布局 | 定位 | 页面数 |
|---|---|---|---|
| 管理员端 | Layout.vue（10 域菜单 + Tab 页签 + 全局搜索 + Agent 入口） | 平台治理/研发/运维/安全 | 47 路由 |
| 用户端 | UserLayout.vue（8 大入口 + 侧栏搜索 + 全局搜索 Ctrl+K + 消息 + 用户菜单） | 警务业务/研判/数据使用/专案 | 40 路由 |
| 兼容层 | 旧路由（/datasource、/workflow 等 57 条） | 历史链接不失效 | - |

## 二、登录分流与权限体系

### 2.1 登录分流
- `POST /api/auth/login` 返回 `user.roles`（后端 zy_user_role → zy_role.code）
- 前端：`roles.some(r => /ADMIN|DEVELOPER|AUDITOR|SECURITY/i.test(r))` → `/admin/dashboard`，否则 `/workbench`

### 2.2 权限模型（Pinia permission store）
| 状态 | 说明 |
|---|---|
| roles | 角色集合 |
| permissions | 操作权限编码（`workflow:execute` 等，待后端 /api/auth/permissions 填充） |
| dataScopes | 数据范围（ALL/TENANT/ORG/SELF/PROJECT/CUSTOM） |
| securityLevel | 用户最高密级（L1-L4） |
| projectScopes | 授权专案 |

- `v-permission` 指令：无权限自动移除按钮
- 路由 `meta.permission` + `meta.securityLevel`：页面级声明（情报检索 L4 / 对象研判·图谱 L3）
- 页面统一"权限继承"提示条：数据范围 + 密级 + 专案范围 + 字段脱敏后端二次校验

### 3.3 管理员核心页（功能要点）
- **数据源**：插件化类型（MySQL/CH/Iceberg/Kafka）、动态表单、能力徽标、元数据面板、SQL 预览
- **工作流**：13 类节点 DAG（含湖仓同步/分析加载）、数据范围校验（危险写拦截）、调度执行
- **湖仓管理**：快照/时间旅行读取/JSON 追加写入/注册为数据源
- **引擎作业**：Spark/Flink + 5 类作业模板 + 资源配额
- **数据接入**：CDC 链路卡（演示事件/采集对账/断点位点）+ 实时质量
- **血缘分析**：三布局图 + 节点筛选（表/字段/任务/接口/文件）+ 影响分析/环检测/热度/SQL 解析
- **结构采集**：已采集元数据 + 统一元数据目录（跨源聚合）
- **质量规则**：规则 CRUD + 执行 + 实时质量页签

## 七、路由 / 状态 / 权限实现

### 7.1 路由（144 条）
- `/admin/*`：47 条（管理员布局）
- `/workbench/*`：40 条（用户布局，meta 带 permission/securityLevel）
- 旧路由 57 条：兼容保留
- 守卫：登录检查（token）；`meta.permission`/`securityLevel` 预留（权限 store 接入后启用）

### 7.2 状态（Pinia）
- auth：token/user/isLoggedIn
- permission：roles/permissions/dataScopes/securityLevel/projectScopes + hasPermission/hasRole/canAccessLevel/isAdminWorkspace

### 7.3 权限指令
- `v-permission="'workflow:execute'"`：无权限移除按钮（全局注册）
